# Proboi Privacy Module

Модуль приватности платформы Proboi. Ставится на машину клиента (внутри его периметра)
и обеспечивает: **шифрование всех приватных данных ключами клиента** и
**де-идентификацию текста до любого выхода данных за периметр** — в том числе до
трансграничной передачи в облачные LLM.

Исходный код опубликован, чтобы служба ИБ заказчика могла **проверить каждое из этих
утверждений по коду, а не по маркетинговым материалам**: прочитать, собрать, прогнать
тесты и убедиться, что именно уходит наружу, а что не покидает периметр никогда.

## Гарантии (сверяемые по коду)

| Данные | Что видит внешняя сторона (наш CORE / облачная LLM) | Ключ |
|---|---|---|
| Оригиналы файлов, сканы, логи, таблицы (at-rest) | Ничего — шифртекст AES-256-GCM | У клиента |
| ФИО, организации, номера дел, даты | Токены `[PER_01]`, `[ORG_01]`, … | Словарь токенов — только локально |
| Обезличенная структура текста | Уходит по TLS — это то, что модель обязана прочитать, чтобы работать | — |

Модуль — конструктор: каждый компонент ставится и включается отдельно, наборы под
домен задаются профилями ([src/profiles.ts](src/profiles.ts)). В таблице выше —
базовый контур; опциональные компоненты (гео-обезличка, Python-сайдкар) описаны ниже
и ставятся только тем, кому нужны.

**Честный предел, зашитый в дизайн:** де-идентификация ≠ шифрование содержимого.
Облачная модель обязана видеть текст, иначе не сможет его обработать. Модуль снимает
*идентифицируемость* (кто/где), но анонимные числа и структура документа уходят в
модель по шифрованному каналу. Кому нужно, чтобы облако не видело вообще ничего, —
для этого предусмотрен on-prem-тир (локальное распознавание, данные не покидают
периметр; поставляется отдельно).

## Крипто-спецификация

Всё — стандартные примитивы WebCrypto / node:crypto, без самодельной криптографии.

- **Envelope-шифрование** ([src/components/envelope.ts](src/components/envelope.ts)):
  на каждый объект генерируется свой DEK (AES-256-GCM, 12-байтовый IV, 16-байтовый
  auth-tag). DEK заворачивается KEK-ом через AES-KW. Порча шифртекста или неверный
  ключ → GCM auth fail, расшифровка невозможна.
- **Защита KEK** ([src/components/keys.ts](src/components/keys.ts)) — два слоя:
  1. recovery-passphrase → scrypt (N=65536, r=8, p=1 — прод-уровень OWASP) → AES-KW;
  2. на Windows — DPAPI (user-scope, `CRYPTPROTECT_UI_FORBIDDEN`) через FFI:
     ключ привязан к учётной записи, другой пользователь машины или украденный диск
     его не прочтут. Вне Windows фолбэк **fail-closed**: запускается только явным
     флагом «незащищённый dev-режим» и громко предупреждает.
- **Egress-gate** ([src/egress-gate.ts](src/egress-gate.ts)): единая точка выхода
  текста наружу. **Fail-closed**: если де-идентификация упала — исключение
  пробрасывается наверх и отправка блокируется; сырой текст наружу не уходит.
  Каждый выход фиксируется квитанцией (число сущностей, профиль, хэш текста после
  редакции) в аудит-лог.

## Де-идентификация

- **Текст** ([src/components/text-deid.ts](src/components/text-deid.ts),
  [src/deid/detect.ts](src/deid/detect.ts)): распознавание сущностей
  PER / ORG / DATE / CASE, замена на стабильные токены. Соответствие
  «токен ↔ оригинал» хранится в локальном vault ([src/vault.ts](src/vault.ts)) и
  не покидает периметр; ответ модели ре-идентифицируется обратно на стороне клиента.
- **Геоданные — опциональный компонент** ([src/geo/](src/geo/)): нужен только тем,
  у кого в документах есть реальные координаты (недра, изыскания, кадастр). Делает
  обратимую трансформацию координат в «местную систему координат» (proj4): наружу
  уходят координаты, не привязанные к реальной местности, параметры обратной
  трансформации — только у клиента. Если с координатами не работаете — компонент
  просто не ставится и в контуре не участвует.
- **Python-сайдкар — опциональный компонент** ([src/py-sidecar/](src/py-sidecar/)):
  Natasha (русский NER) для повышенного recall. Крутится на loopback той же машины,
  наружу не ходит. Дефолтный TS-путь работает без него.
- **Профили** ([src/profiles.ts](src/profiles.ts)): готовые наборы компонентов под
  домен (базовый / юридический / гео).

## Что это значит для трансграничной передачи

За границу периметра уходят только: (1) шифртекст, ключи от которого держит клиент,
и (2) обезличенный текст, из которого удалены идентифицирующие сущности, — по TLS.
Идентифицирующие данные (ФИО, организации, реальные координаты, оригиналы документов)
в открытом виде периметр не покидают. Квитанции egress-gate дают проверяемый след
каждой отправки. Оценку применимости этой схемы к конкретным требованиям
(152-ФЗ, внутренние политики) ИБ заказчика может делать по этому коду.

## Как аудировать

```bash
bun install
bun test        # 164 теста: крипто round-trip, fail-closed, PII-утечки, гео-обратимость
bun x tsc --noEmit
```

Рекомендуемый порядок чтения: `src/types.ts` → `src/components/envelope.ts` →
`src/components/keys.ts` → `src/egress-gate.ts` → `src/pipeline.ts`.
Тесты (`*.test.ts` рядом с кодом) — исполняемая спецификация: в том числе
адверсариальные проверки «PII не уходит при включённом модуле» и
«fail-closed при падении де-ида».

Один Windows-only тест (реальный DPAPI round-trip) в CI пропускается — его можно
прогнать на любом Windows-стенде.
